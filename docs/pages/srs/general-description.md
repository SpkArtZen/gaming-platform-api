# 2. General Description

## 2.1 Product Perspective

The Gaming Platform API is a new, self-contained backend. Client applications (a web store, a mobile app, an admin panel) talk to it over HTTPS. Internally the API stores data in a relational database.

| Component | Role |
| --- | --- |
| Client applications | call the API directly or through the SDK |
| Gaming Platform API | business logic, validation, access control |
| Database | persistent storage of games, players and libraries |
| Identity provider | issues JWT access tokens (outside this product) |
| Documentation site (Zudoku on GitHub Pages) | API reference, guides and this SRS |

## 2.2 Product Functions

- Browse the game catalogue with pagination and filters by genre, platform and title.
- Add, update and delete games in the catalogue.
- Register players and edit or delete their profiles.
- Keep a personal game library for every player.
- Protect all write operations and all player data with token-based authorization.

## 2.3 User Classes and Characteristics

| User class | Description | Access |
| --- | --- | --- |
| Guest | anyone, including client apps before sign-in | browse and search the catalogue |
| Player | a registered user with a valid token | own profile and own library |
| Catalogue manager | staff member who maintains the catalogue | create, update and delete games |
| Client developer | builds apps on top of the API | documentation, OpenAPI file, SDK |

Users are expected to be familiar with ordinary web and mobile apps. Client developers are expected to know HTTP, JSON and TypeScript or another language with an OpenAPI generator.

## 2.4 Benefits

- One source of truth: the OpenAPI document drives the SDK and the documentation, so they never disagree.
- New clients start faster with the generated SDK.
- The public catalogue can be shown to visitors without sign-in.

## 2.5 Operating Environment

- Server: Linux container, Node.js 22 LTS, PostgreSQL 16.
- Clients: any HTTP client that supports TLS 1.2+; SDK — Node.js 18+ or a modern browser.
- Documentation: static site on GitHub Pages.

## 2.6 Assumptions and Dependencies

- Access tokens are issued by an external identity provider; the API only verifies them.
- Prices are stored in US dollars; currency conversion is not required.
- Game identifiers and player identifiers are UUIDs generated by the server.
